# Changelog

All notable changes to **smithy-beam** are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **`BodySpec.nestedWireNameOverrides()`** — second `Map<String, String>` field on the `BodySpec` IR record storing shallow `@xmlName` / `@ec2QueryName` renames for the direct members of each top-level input member's target structure (or list-element structure). A backward-compatible 4-arg convenience constructor delegates to the canonical 5-arg form with an empty map, so all non-EC2 analyzers are unaffected.
- **`aws_query:rename_map_keys/2`** — new exported function in the `aws_query.erl` runtime module. Applies a shallow key-rename map to a single map or to every element of a list of maps, passing through `undefined` and scalar values unchanged. Called by generated EC2 client code to apply nested `@xmlName` overrides (e.g. `Tags` → `Tag` inside `TagSpecification`) before the query encoder flattens the structure.

### Fixed

- **`RestXmlProtocolAnalyzer`**: `analyzeClientOperation` now inspects the output shape in addition to the input shape. Reuses `RestJsonProtocolAnalyzer.buildResponsePayloadMember`, `buildResponseCodeMember`, and `buildResponseHeaders` helpers and passes the results to the full `OperationSpec` constructor. Previously the convenience constructor was used, leaving `responsePayloadMember` always null; S3 `GetObject`'s raw blob body was passed to `aws_xml:decode`, producing an `{xml_parse_error, …}` failure.
- **`ErlangWriter` — `appendHttpcCall`**: the success branch is now split into three distinct cases. (1) `@httpPayload` or `@httpResponseCode` present: result map assembled from explicit HTTP bindings only; body placed raw under the payload member key. (2) Only `@httpHeader` bindings present: body decoded as XML or JSON as usual, then `maps:merge`d with a `HeaderMap` of extracted response header values. (3) No response bindings: unchanged standard decode path. Previously a single `hasResponseBindings` branch skipped body decoding for any operation with output header bindings, causing S3 `ListObjects` to return `#{}` when response headers were absent from the reply.
- **`Ec2QueryProtocolAnalyzer`**: extended to collect nested wire-name overrides in addition to top-level ones. A new `collectNestedMemberRenames/2` helper resolves each top-level input member's target structure (or list-element structure) and records `@ec2QueryName` / `@xmlName` differences into `BodySpec.nestedWireNameOverrides()`. The `ErlangWriter` then emits `aws_query:rename_map_keys/2` calls for each affected member before encoding, covering structures like `TagSpecification` where `Tags` must be serialized as `Tag`.
- **`ElixirWriter` — `renderUnionType`**: union type names are now run through `ElixirReservedWords.escapeTypeName` (the same guard applied in `renderStructType` and `renderEnumType`), preventing a compile error when a union shape name maps to an Elixir built-in type name such as `map`, `node`, or `list`.
- **`ElixirWriter` — `typeRefToElixir`**: `TypeRef.Named` references now resolve via `ElixirSymbolProvider.toInlineTypeName` instead of `toSnakeCase + "()"`, so the `_t` suffix is consistently applied in field type annotations, `@spec` parameters, and `@callback` return types when the referenced shape name is an Elixir built-in.

### Added

- **`examples/elixir/ec2-demo`**, **`examples/elixir/s3-demo`**, **`examples/elixir/ssm-demo`**: three Elixir AWS client demo applications. `ec2-demo` targets `aws.protocols#ec2Query` (DescribeVpcs, DescribeSecurityGroups, RunInstances, DescribeInstances, TerminateInstances). `s3-demo` targets `aws.protocols#restXml` (ListBuckets, PutObject, ListObjects, GetObject). `ssm-demo` targets `aws.protocols#awsJson1_1` (DescribeParameters, GetParameter, GetParameters, GetParametersByPath, PutParameter, GetParameterHistory, ListTagsForResource, DeleteParameter). Each demo uses incremented `HOST_PORT` values (4577 / 4578 / 4579) and includes Terraform provisioning for LocalStack.
- **`SmithySigV4`** in `runtime-elixir/client/` (renamed from `SmithyAuth`): AWS Signature Version 4 signing — `sign_request/2` adds `Authorization` and `X-Amz-Date` headers (and `X-Amz-Security-Token` when a session token is present). Credentials are read from `config.credentials` when nested, falling back to the top-level config. Service name is derived from the endpoint URL when absent from config.
- **`SmithyCredentials`** in `runtime-elixir/client/`: AWS credentials provider. Loads credentials from environment variables (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`) or `~/.aws/credentials`. Ported from `aws_credentials.erl`.
- **`SmithyRetry`** in `runtime-elixir/client/`: retry with exponential backoff and jitter. Ported from `aws_retry.erl`.
- **`SmithyXml`** in `runtime-elixir/client/`: XML encode/decode for REST-XML and EC2 Query protocols. Accesses xmerl tuples via `elem/2` to avoid a compile-time dependency on `xmerl/include/xmerl.hrl`, which is unavailable in some Mix environments.
- **`SmithyQuery`** in `runtime-elixir/client/`: AWS Query protocol encoder. Flattens nested maps into dot-notation keys with 1-based list indexing. Ported from `aws_query.erl`.
- **`SmithyS3`** in `runtime-elixir/client/`: S3 URL building and Content-MD5 helpers. Supports virtual-hosted and path-style URL construction. Ported from `aws_s3.erl`.

### Changed

- **`SmithyClient`** — `request/3` and `stream/3`: the client execution functions now take `(client, %Operation{}, opts)` where `client` is the config map returned by `new/1` and `opts` is a plain map of call-level options (e.g. `%{enable_retry: false}`). This matches the 3-argument convention used across the Erlang SDK.
- **`ElixirWriter` — `renderClientOperation`**: generated operation functions now have the signature `def <op>(client, input, opts \\ %{})`. They delegate to `SmithyClient.request/3` via a private `defp <op>_op(input)` builder that returns the `%SmithyClient.Operation{}` struct. Pagination stream helpers are generated as `def <op>_stream(client, input, opts \\ %{})` and call `SmithyClient.stream/3` using the same private builder.

### Fixed

- **`ElixirWriter` — enum codec generation**: enum values containing dots (e.g. `"Automation.ChangeTemplate"`) were lowercased to `automation.changetemplate` and prefixed with `:`, which Elixir parses as a remote function call and rejects in pattern-match position. Atom literals with special characters are now wrapped in `:"…"` quoted-atom syntax.
- **`ElixirReservedWords` / `ElixirSymbolProvider` — built-in type name collision**: Smithy shape names that map to Elixir built-in type names (e.g. `Node` → `node`) caused a compiler error because `@type node :: …` is forbidden. A `BUILTIN_TYPES` set and `escapeTypeName()` helper now append `_t` to any conflicting name (e.g. `node_t`), applied consistently in `renderStructType`, `renderEnumType`, and `toInlineTypeName`.
- **`ClientPipeline` — duplicate pagination helper**: the `_stream` function was generated twice for every paginated operation because `ClientPipeline` called `renderPaginationHelper` separately after `renderClientOperation`, which already emits the helper internally. The redundant call in `ClientPipeline` is removed.

### Added

- **`ElixirClientPlugin`** (`elixir-client-codegen`) and **`ElixirServerPlugin`** (`elixir-server-codegen`) in `codegen-elixir`: fully wired Smithy Build plugins registered via `META-INF/services`. Both resolve the active protocol via `ProtocolAnalyzerFactory`, instantiate `ElixirWriter`, and invoke the shared `ClientPipeline` / `ServerPipeline`. The server plugin generates `<svc>_server.ex` (Plug.Router dispatcher + Handler behaviour) and writes the impl scaffold once via `writeIfAbsent`. Runtime modules from `runtime-elixir/` are bundled into the JAR under `META-INF/smithy-beam/runtime/elixir/` and copied alongside generated files.
- **`SmithyErrorMap`** runtime module in `runtime-elixir/server/`: Elixir port of `smithy_error_map.erl`. Maps Smithy error terms (`{:not_found, msg}`, `{:conflict, msg}`, `{:unauthorized, msg}`, `{:forbidden, msg}`, `{:internal, msg}`, `{:validation, msg}`, `:not_implemented`) to `{http_status_code, message}` pairs. Serves as the generic fallback; generated per-service overrides prepend clauses for modelled `@httpError` shapes.
- **`renderServerImplContent/2`** extension point in `LanguageWriter` (default returns `""`): writers override this to produce language-correct impl scaffold content. When non-empty, `ServerPipeline` uses it instead of the generic `buildImplScaffold`, allowing dot-notation module names for Elixir (`WeatherService.Impl` / `WeatherService.Handler`) without coupling the pipeline to any target language's naming conventions.
- **`examples/elixir/weather-service`**: working end-to-end example using `aws.protocols#restJson1` — a Plug.Router-based Elixir server generated by `elixir-server-codegen`. Covers GET with `@httpLabel`, POST with JSON body, `@enum` wire values, and `@httpError` error shapes. Includes `smithy-build.json`, `mix.exs` (Plug, Bandit, Jason), and `Plug.Test` round-trip tests for GET 200, POST 201, GET 404, and POST 404 cases.

### Fixed

- **`ElixirWriter` — `renderServerDeserialize`**: body members are now read via `Plug.Conn.read_body(conn)` + `Jason.decode(body_raw)` instead of the incorrect `conn.body_params` access. `body_params` is unfetched in Plug without an explicit body parser; reading the raw body directly works regardless of middleware configuration.
- **`ElixirWriter` — `renderServerModule`**: no longer embeds the `WeatherService.Impl` stub in the generated server file. The impl scaffold is written as a separate once-written file by `ServerPipeline`, avoiding a module-redefinition conflict when both the dispatcher and the user's impl are compiled together.
- **`SmithyServer.response/3`**: now accepts both a `binary()` (already-encoded, as returned by generated `serialize_*` helpers that call `Jason.encode!`) and any other term (encoded here). Previously passing a pre-encoded binary caused double-encoding, producing a JSON-stringified string instead of the intended JSON object.
- **`ServerPipeline.buildImplScaffold`**: adds `writer.moduleFooter()` at the end of the generated impl scaffold, producing well-formed output for languages such as Elixir that require an explicit module closing keyword.

- **`ElixirSymbolProvider`** in `codegen-elixir` (`symbol` package): converts Smithy names to idiomatic Elixir identifiers — `moduleName` (PascalCase preserved), `functionName`/`varName` (PascalCase → `snake_case`), `typeName` (`ModuleName.t()`), `mapKey` (`:atom` key). `ElixirReservedWords` guards against collisions with Elixir and Kernel built-in names by appending `_`.
- **`ElixirWriter`** in `codegen-elixir`: full `LanguageWriter` implementation for Elixir.
  - Module structure: `moduleHeader` (`defmodule … do`), `moduleFooter` (`end`), `exportSection` (no-op — all `def` functions are public in Elixir), `renderModuleComment` (`@moduledoc`), `behaviourDeclaration` (`@behaviour`), `renderToolingAttributes` (no-op).

  - Map operations: `renderMapGet` (`Map.get/3` with atom key), `renderMapBuild` (`%{key: value}` map literal).

  - Shared helpers: `renderSharedHelpers` (`url_encode/1` and `ensure_string/1`).
  - Client: `renderClientConstructor` (`def new(config)`), `renderClientOperation` (`def <op>(client, input, opts \\ %{})` delegating to `SmithyClient.request/3` via a private `defp <op>_op(input)` builder; emits a `def <op>_stream(client, input, opts \\ %{})` pagination helper via `SmithyClient.stream/3` when `@paginated`), `renderPaginationHelper`, `clientRuntimeModules` (selects `.ex` runtime files based on SigV4/XML/query/S3 requirements).
  - Error serialization: `renderErrorSerializer` and `renderModuleParseError` (protocol-aware; by error code string for REST-XML, by HTTP status code for REST-JSON).
  - Server: `renderServerCallbackDeclaration` (`@callback`), `renderServerRouteClause` (Plug `get`/`post`/`match` macro), `renderServerRouteFallback` (`match _ do`), `renderServerDeserialize` (extracts path params via `conn.path_params`), `renderServerSerialize` (`Jason.encode!`), `renderServerImplStub` (`{:error, :not_implemented}`), `serverRuntimeModules`.

- **Elixir server runtime modules** in `runtime-elixir/server/`: two new modules providing HTTP dispatch helpers and input validation as the runtime foundation for generated Elixir server dispatchers.
  - **`SmithyServer`**: Plug-compatible HTTP abstraction layer — `extract/1` reads method, path, headers, and body from a `Plug.Conn`; `response/3`, `error_response/2`, `validation_error/2`, and `not_found/1` build and send JSON responses. Delegates error-to-status mapping to `SmithyErrorMap.to_http/1` and validation message formatting to `SmithyValidator.format/1`.
  - **`SmithyValidator`**: required-field validation — `validate/2` checks that all required keys are present in an input map and returns `:ok` or `{:error, {:missing_required_fields, [term()]}}`. `format/1` converts the error term to a human-readable string (`"Missing required fields: …"`).

Internal helpers cover canonical request construction, query string canonicalization, header canonicalization, HMAC-SHA256 key derivation, and signature calculation.

## [0.1.0] — 2026-04-13

### Added

- **`OperationSpec`** extended with three new response-binding fields in `codegen-core/ir`: `responsePayloadMember` (name of the `@httpPayload` output member; the raw response body is placed under this key without JSON-decoding), `responseCodeMember` (name of the `@httpResponseCode` output member; the HTTP status integer is placed under this key), and `responseHeaders` (list of `HeaderBinding` entries for `@httpHeader`-annotated output members; each is extracted from the response headers and placed in the result map). A backward-compatible 18-arg convenience constructor delegates to the canonical 21-arg form with `null`/`List.of()` defaults, so all existing non-restJson protocol analyzers are unaffected.

- **`BodySpec.wireNameOverrides()`** — new `Map<String, String>` field on the `BodySpec` IR record storing per-member Smithy-name → wire-name overrides collected at codegen time. A backward-compatible 3-arg convenience constructor delegates to the canonical 4-arg form with an empty map, so all non-EC2 protocol analyzers are unaffected.
- **`apiVersion` field** on `OperationSpec` IR record: carries the service API version string (e.g. `"2016-11-15"`) so the Erlang writer can pass it as the third argument to `aws_query:encode/3` without re-analyzing the model. Null for protocols that do not embed a version in the request body.
- **`aws_query:unwrap_response/1`** — new function in the `aws_query.erl` runtime module. Strips the outer `<XyzResponse>` wrapper always present in AwsQuery and EC2 Query responses, then strips an inner `<XyzResult>` wrapper when one exists, returning `{ok, InnerMap}` with the actual response data.
- **`examples/erlang/ec2-demo`** — Erlang client example using `aws.protocols#ec2Query` (Amazon EC2). Covers instance lifecycle (RunInstances, DescribeInstances, TerminateInstances), VPC and security-group enumeration, and `@ec2QueryName`-remapped member names. Includes `smithy-build.json`, `rebar.config`, `app.src`, Makefile, and Terraform config.
- **`examples/erlang/iam-demo`** — Erlang client example using `aws.protocols#awsQuery` (Amazon IAM). Covers user/group lifecycle (ListUsers, GetUser, CreateUser, ListGroups, ListGroupsForUser, AddUserToGroup).
- **`examples/erlang/sns-demo`** — Erlang client example using `aws.protocols#awsQuery` (Amazon SNS). Covers topic lifecycle (CreateTopic, ListTopics, Subscribe, Publish, Unsubscribe, DeleteTopic).
- **`examples/erlang/rds-demo`** — Erlang client example using `aws.protocols#awsQuery` (Amazon RDS). Covers DB instance lifecycle (CreateDBInstance, DescribeDBInstances, DeleteDBInstance).
- **`examples/erlang/sqs-demo`** — Erlang client example using `aws.protocols#awsJson1_0` (Amazon SQS). Covers queue lifecycle (CreateQueue, ListQueues, SendMessage, ReceiveMessage, DeleteMessage, DeleteQueue).
- **`examples/erlang/firehose-demo`** — Erlang client example using `aws.protocols#awsJson1_1` (Amazon Kinesis Data Firehose). Covers delivery stream lifecycle (CreateDeliveryStream, DescribeDeliveryStream, PutRecord, DeleteDeliveryStream).
- **`examples/erlang/kinesis-demo`** — Erlang client example using `aws.protocols#awsJson1_1` (Amazon Kinesis). Covers data stream lifecycle (CreateStream, DescribeStream, PutRecord, GetRecords, DeleteStream).
- **`examples/erlang/ssm-demo`** — Erlang client example using `aws.protocols#awsJson1_1` (Amazon Systems Manager). Covers parameter lifecycle (PutParameter, GetParameter, DeleteParameter).
- **`examples/erlang/lambda-demo`** — Erlang client example using `aws.protocols#restJson1` (AWS Lambda). Covers function lifecycle (CreateFunction, GetFunction, InvokeFunction, DeleteFunction).
- **Erlang server runtime modules** in `runtime-erlang/server/`: three new modules providing HTTP dispatch helpers, input validation, and error mapping as the runtime foundation for generated Erlang server dispatchers.
  - **`smithy_server`**: HTTP abstraction layer — `extract/1` reads method, path, headers, and body from a Cowboy request; `response/2`, `error_response/1`, `validation_error/1`, and `not_found/0` return framework-agnostic `{StatusCode, Headers, Body}` tuples consumed by the generated dispatcher and the application's Cowboy handler.
  - **`smithy_validator`**: required-field validation — `validate/2` checks that all required binary-keyed fields are present in an input map and returns `ok` or `{error, {missing_required_fields, [binary()]}}`. `format/1` converts the error term to a human-readable binary message (`<<"Missing required fields: …">>`).
  - **`smithy_error_map`**: error-to-HTTP mapping — `to_http/1` maps Smithy error atoms and tuples (`{not_found, Msg}`, `{conflict, Msg}`, `{unauthorized, Msg}`, etc.) to `{HttpStatusCode, MessageBinary}` pairs. Serves as the generic fallback for generated per-service overrides that add modeled `@httpError` shapes.
- **Unit tests** for all three Erlang server runtime modules in `runtime-erlang/server/test/`, verified with `rebar3 eunit`. Includes `cowboy_req.erl` — a test-only mock accepting plain maps — so `smithy_server:extract/1` can be exercised without a live Cowboy server.
- **Test harness improvement** (`Makefile`, `test/runtime-erlang` target): adds `jsx` as an eunit dependency, redirects all output to `erlang-runtime-test.log`, and detects failures and syntax errors via `grep` with a clear exit code and log reference.

- **`ErlangReservedWords`** in `codegen-erlang` (`symbol` package): complete set of Erlang reserved words with `isReserved()` and `escape()` helpers; reserved words are escaped by appending `_`.
- **`ErlangSymbolProvider`** in `codegen-erlang` (`symbol` package): converts Smithy names to Erlang identifiers — `toModuleName`/`toFunctionName` (PascalCase → snake_case), `toTypeName` (snake_case with trailing `()`), `toVarName` (PascalCase for Erlang variable syntax), and internal `toSnakeCase`/`toPascalCase` helpers. New `toAtomTag(name)` static helper converts member names to Erlang atom tags, wrapping Erlang reserved words in single quotes (e.g. `'and'`, `'end'`) so they remain syntactically valid.
- **`ErlangWriter`** in `codegen-erlang`: full `LanguageWriter` implementation replacing the empty stub.
  - Module structure: `moduleHeader` (`-module`), `exportSection` (multiline `-export`, one entry per line), `exportTypes` (multiline `-export_type`), `renderModuleComment` (`%% Generated Smithy client for <Service>`), `behaviourDeclaration` (`-behaviour`), `moduleFooter` (empty — Erlang has no footer).
  - Type rendering: `renderStructType` (Erlang map type with `=>` for all fields; required annotation enforced at call sites via `validate_*` helpers), `renderEnumType` (union of lowercase atoms, e.g. `celsius | fahrenheit`), `renderUnionType` (tagged tuples), `renderCallbackDeclaration` (`-callback`), `renderFunctionSpec` (`-spec`), `renderFunctionHead`, `renderFunctionEnd`.
  - Map operations: `renderMapGet` (`maps:get/3` with binary key), `renderMapBuild` (map literal with binary keys).
  - Serialization: `renderJsonEncode`/`renderJsonDecode` (`jsx`), `renderXmlEncode`/`renderXmlDecode` (`aws_xml`), `renderFormEncode` (`aws_query`).
  - HTTP: `renderUriSubstitution` (Erlang binary string with label interpolation and optional `url_encode`), `renderQueryStringBuilder` (`uri_string:compose_query` with `ensure_binary/1` coercion for all values), `renderHeaderBuilder` (protocol-correct `Content-Type` base header with numbered accumulator variables `Headers0`, `Headers1`, …; literal `X-Amz-Target` value emitted for AWS JSON operations), `renderHttpClientBlock` (`httpc:request/4` with success/error pattern matching).
  - Auth and retry: `renderAuthWrapper` (prepends SigV4 signing via `aws_sigv4:sign_request` when required; no-op otherwise), `renderRetryWrapper` (`aws_retry:with_retry`).
  - Response and errors: `renderResponseHandler` (generates `deserialize_<op>/1` extracting body members), `renderModuleParseError` (protocol-aware — see **Fixed** below).
  - Pagination: `renderPaginationHelper` (generates `<op>_stream/2,3` that loops, accumulates items, and threads the output token back as input).
  - Runtime name helpers: `jsonEncodeCall`, `jsonDecodeCall`, `sigv4SignCall`, `retryCall`.
- **`HeaderBinding.literalValue`** field in `codegen-core/ir`: when non-null, the header value is a hard-coded string constant emitted verbatim rather than read from the caller's `Input` map. Used for `X-Amz-Target` in AWS JSON protocols.
- **`OperationSpec`** extended with five new fields in `codegen-core/ir`: `outputTypeName`, `inputTypeName`, `responseEncoding`, `protocolContentType` (wire `Content-Type`, e.g. `"application/x-amz-json-1.0"`), and `protocolErrorStrategy` (one of `REST_XML`, `AWS_JSON`, `REST_JSON`, `AWS_QUERY`). Writers use these to emit protocol-correct wire code without re-analyzing the model.
- **`LanguageWriter`** interface extended in `codegen-core/writer`: new default and abstract methods — `renderModuleComment`, `renderToolingAttributes`, `exportTypes`, `renderClientConstructor`, `renderClientOperation`, `renderEnumCodec`, `renderUnionCodec`, `renderValidateHelper`, `renderSharedHelpers`, `clientRuntimeModules`, and a protocol-aware overload `renderModuleParseError(errors, ErrorCodeStrategy)`.
- **`ClientPipeline`** in `codegen-core`: fully implemented end-to-end Erlang client module generation.
  - Emits `-module`, `-export` (multiline), `-export_type` (multiline), and `-dialyzer` attributes, plus a module-level comment.
  - Renders all struct/enum/union/error type definitions in order.
  - Generates `new/1` constructor with `-spec` annotation.
  - Generates a 3-function block per operation: 2-arity public wrapper, 3-arity options/retry wrapper, and an internal `make_<op>_request/2` that builds the full URL (URI label substitution + query strings, with S3-specific `aws_s3:build_url` for S3 services), constructs the request body (JSON or form-encoded; direct `jsx:encode(Input)` for AWS JSON protocols), sets headers with the protocol-correct `Content-Type`, conditionally signs with SigV4, calls `httpc:request/4`, and decodes the response or dispatches to `parse_error/2`.
  - Generates `url_encode/1` and `ensure_binary/1` internal helpers.
  - Generates `encode_<enum>/1` and `decode_<enum>/1` helpers using lowercase atom representation for enum values.
  - Generates `encode_<union>/1` and `decode_<union>/1` helpers using nested `maps:find` dispatch for all union types.
  - Generates `validate_<struct>/1` helpers restricted to operation input types (not all structs).
  - Generates a single module-level `parse_error/2` function, deduplicated by Smithy error name across all operations, with protocol-specific dispatch and return format.
  - Conditionally copies `aws_sigv4.erl` and `aws_credentials.erl` runtime modules when any operation requires SigV4; always copies `aws_retry.erl` and `aws_config.erl`.
- **`analyzeServerOperation`** in `RestJsonProtocolAnalyzer` and `AwsJsonProtocolAnalyzer` — server-direction counterpart to `analyzeClientOperation`; produces `OperationSpec` IR with the same HTTP binding analysis (method, URI template, label bindings, header bindings, body members) used by the server pipeline to generate routing and deserialization logic.
- **Server rendering methods in `ErlangWriter`** — full set of server-side rendering delegated from `ServerPipeline` and assembled by `renderServerModule`:
  - `renderServerCallbackDeclaration(op)` — `-callback <op>(Input :: <op>_input(), Context :: map()) -> {ok, <op>_output()} | {error, term()}.`
  - `renderServerRouteClause(op)` — one semicolon-terminated `route/2` clause per operation; restJson1 routes on HTTP method + URI prefix; awsJson routes on `X-Amz-Target` binary.
  - `renderServerRouteFallback()` — `route(_, _) -> {error, not_found}.`
  - `renderServerHandleFunction(ops, svcModuleName)` — `handle/3` that calls the router module; used in the multi-file layout (now superseded by `renderServerModule`).
  - `renderServerDispatchClause(op)` — `dispatch_<op>/5` that deserializes input, calls `Impl:<op>/2`, and serializes or propagates errors.
  - `renderServerDeserialize(op)` — `deserialize_<op>/3` that extracts path labels and body members; awsJson variant decodes the full body map.

- **`ServerPipeline`** in `codegen-core` — fully implemented end-to-end server orchestrator. Calls `writer.renderServerModule(base, ops, types)` and writes the result to `<outDir>/<base>_server<ext>` when non-empty (guarded so writers that do not override `renderServerModule` are safe). Writes the impl scaffold once via `writeIfAbsent`; scaffold declares `-behaviour(<base>_server)` and remote-typed `-spec` declarations qualified with `<base>_server:<type>()`. Runtime modules are copied via `writer.serverRuntimeModules()`. Contains no target-language string literals.

Delegates entirely to `ServerPipeline`; generates two files per service: `<svc>_server.erl` (consolidated module) and `<svc>_impl.erl` (once-written stub scaffold, never overwritten on subsequent runs).

### Fixed

- **`ErlangWriter` — `appendBody`**: when an operation's input has an `@httpPayload` member, the generated code now sends that member's value directly as the raw request body (`Body = maps:get(<<"Member">>, Input, <<>>)`) instead of wrapping it in a JSON map (`#{<<"Member">> => ...}`). Previously the generated client sent `{"Payload": "..."}` rather than the raw blob.
- **`ErlangWriter` — `appendHttpcCall`**: when an operation's output has any `@httpPayload`, `@httpResponseCode`, or `@httpHeader` binding, the success branch now builds the result map from those HTTP bindings instead of JSON-decoding the body. Specifically: the raw response body is placed under the `@httpPayload` member name without decoding; the HTTP status code integer is placed under the `@httpResponseCode` member name; each `@httpHeader`-bound output member is extracted from the response header list via `proplists:get_value/2` and converted from a string to a binary. `maps:filter` removes any absent (undefined) headers from the result map.
- **`RestJsonProtocolAnalyzer`**: `analyzeClientOperation` now inspects the output shape in addition to the input shape. Three new static helpers — `buildResponsePayloadMember`, `buildResponseCodeMember`, and `buildResponseHeaders` — walk the output `StructureShape` and populate the corresponding new `OperationSpec` fields so the writer can emit correct response-handling code without re-analyzing the model.

- **`AwsQueryProtocolAnalyzer`**: `requiresXmlRuntime()` now returns `true` so that `aws_xml.erl` is copied into the build output for awsQuery services, matching the behavior already present for EC2 Query.
- **`AwsQueryProtocolAnalyzer`**: `apiVersion` is now propagated from the service shape into `OperationSpec`, enabling `aws_query:encode/3` to include the `Version` parameter in form-encoded bodies.
- **`aws_query:encode/3`** arity call fixed in generated `make_<op>_request/2` functions: the third argument (api version string) is now passed correctly. Previously the generated call silently fell through to the 2-arity `encode/2` clause, omitting the `Version` query parameter.
- **`ErlangWriter` — `appendHttpcCall`**: AwsQuery and EC2 Query success responses are now unwrapped before being returned to the caller. The generated success branch decodes the XML body and pipes it through `aws_query:unwrap_response/1`, stripping the outer `<XyzResponse>` and optional inner `<XyzResult>` wrappers. Previously, the full XML tree was returned, causing callers to find response keys buried several levels too deep.
- **`ErlangWriter` — `appendHttpcCall`**: EC2 error responses in `<Response><Errors><Error>` format are now matched and dispatched to `parse_error/2`. Previously, only the IAM/SNS `<ErrorResponse><Error>` format was handled; EC2 error bodies fell through to the `{error, {http_error, Body}}` fallback.
- **`ec2-demo` — `aws_demo_app.erl`**: `DescribeInstances` and `TerminateInstances` input maps now use `<<"InstanceIds">>` (plural), matching the Smithy member name. The previous `<<"InstanceId">>` (singular) key was silently dropped by the generated body builder, causing EC2 to respond with "No instances specified".
- **`TypeSpecBuilder`**: `TypeRef.Named` instances are now built from `shape.getId().getName()` (the local shape name) instead of `shape.getId().toString()` (the fully-qualified Smithy ID including namespace). Previously, type references such as `example.weather#TemperatureUnit` were emitted verbatim into Erlang type specs, producing a syntax error.
- **`TypeSpecBuilder`**: `EnumSpec` values are now populated from `getEnumValues().values()` (wire string values, e.g. `"Celsius"`) rather than `keySet()` (member names, e.g. `"CELSIUS"`), so generated `encode_<enum>/1` and `decode_<enum>/1` helpers match the JSON wire format.
- **`ErlangWriter`** — `renderEnumType` / `renderEnumCodec`: enum values are now emitted as lowercase atoms (e.g. `celsius`) matching Erlang conventions; `encode_<enum>/1` functions no longer include an `Other` fallthrough clause.
- **`ErlangWriter`** — `renderStructType`: all map fields now use the `=>` operator; required fields are enforced at call sites via `validate_*` helpers rather than in type specs.  Member names that are Erlang reserved words (e.g. `and`, `end`) are wrapped in single quotes via `ErlangSymbolProvider.toAtomTag`.
- **`ErlangWriter`** — `appendHeaders`: header accumulation uses uniquely indexed variables (`Headers0`, `Headers1`, …) to satisfy Erlang's single-assignment rule; `Content-Type` is derived from `op.protocolContentType()` so each protocol emits its correct wire value; the literal `X-Amz-Target` value is emitted directly rather than being read from `Input`.
- **`ErlangWriter`** — `appendBody`: for AWS JSON protocols the body is `Body = jsx:encode(Input)` (full input map, no undefined-member filtering); `Body = <<>>` is only emitted when SigV4 is required and no body members are present.
- **`ErlangWriter`** — `appendQueryString`: all query parameter values are coerced through `ensure_binary/1` before being passed to `uri_string:compose_query/1`, preventing `badarg` crashes for integer members such as `MaxKeys`.
- **`ErlangWriter`** — `appendHttpcCall` and `renderModuleParseError`: protocol-aware error dispatch.
  - `REST_XML` and `AWS_JSON`: the error body is parsed (XML `<Code>` element or JSON `__type` field respectively); `parse_error/2` dispatches on the extracted binary error code string and returns `{error, #{error_type => atom, message => binary()}}` structured maps.
  - `REST_JSON` and `AWS_QUERY`: `parse_error/2` dispatches on the HTTP status code integer and returns `{error, {atom, Body}}` tuples.
  - `parse_error` clauses are deduplicated by Smithy error name across all operations (previously by HTTP status code, which conflated distinct errors sharing the same code).
- **`ClientPipeline`** — `validate_` scope: `validate_<struct>/1` helpers and their `-export` entries are now generated only for shapes that appear as an operation's input type, not for every struct in the model.
- **`ClientPipeline`** — `-export` / `-export_type` declarations are now emitted as multiline blocks (one entry per line) matching standard Erlang style.
- **`ErlangSymbolProvider`** — Erlang reserved words used as enum values or union variant names (e.g. `AND` → `and`) are quoted as `'and'` in generated code instead of being appended with `_`, so the original wire name is preserved.
